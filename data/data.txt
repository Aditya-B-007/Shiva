**Shiva** is a high-performance, modular control-coupling framework written in Rust (featuring C, C++, and Python bindings) designed to bridge reinforcement learning (RL) algorithms with industrial or robotic plant control loops.

### What Shiva Does

Based on its architecture and module layout, Shiva functions as an intelligent middleware orchestrator that couples complex control policies to physical/simulated actuators:

* **Policy & RL Execution Engine:** Implements algorithms such as Constrained Policy Optimization (`cpo.rs`), Twin Delayed DDPG (`td3.rs`), Soft Actor-Critic (`softActorCriticNetwork.rs`), Implicit Quantile Networks (`implicitQuantileNetworks.rs`), and Random Network Distillation (`rnd.rs`).
* **Multi-Node Architecture:**
* **Mothership / Orchestrator:** Oversees lifecycle states, node synchronization, and dispatching.
* **Fast Decision Node:** Low-latency path delivering real-time control actions.
* **Guardrail & Failure Engine:** Safety filtering, constraint handling, and anomaly detection (`brain/anomaly`, `brain/guardrail`) before commands hit hardware.
* **Skill Vault & Long Vision:** Higher-level deliberate planning and modular behavior switching.


* **Middleman Protocol & Adapters:** Decouples the low-level physical system (`actuator_adapter.rs`, `systemSide.rs`) from the learning/inference brain (`shivaSide.rs`, `middleMan.rs`), standardizing observation and actuation matrices.

---

### How Shiva Couples to Any Control Algorithm

Shiva couples to arbitrary control algorithms through a **Sense $\rightarrow$ Guard $\rightarrow$ Actuate** pipeline via its `Adapter` and `MiddleMan` interfaces:

1. **Environment State Ingestion:** The `SystemSide` protocol captures telemetry (encoder values, IMU, process variables) into an `EnvironmentMatrix`.
2. **Adapter Transformation:** The `DefaultInput` / `ActuatorAdapter` maps external system dimensions into the tensor shapes expected by the internal `Brain` / algorithm.
3. **Algorithm Evaluation:** The active control law (e.g., PID, MPC, or RL models like TD3/SAC) computes candidate control signals.
4. **Safety Verification:** The candidate actions pass through `GuardrailNode` / `brain/constraint` to verify that actuator limits, rate limits, and safety invariants are respected.
5. **Actuator Dispatch:** The filtered actions are packaged into `ActuatorSignal` and written back to the plant through the FFI or native Rust hardware driver.

#### 1. Native Rust Control Coupling (`examples/basic_control_loop.rs`)

```rust
use std::time::{Duration, Instant};

// Representation of the internal Shiva architecture modules
pub struct EnvironmentMatrix {
    pub observations: Vec<f64>,
}

pub struct ActuatorSignal {
    pub commands: Vec<f64>,
}

pub trait ControlAlgorithm {
    fn step(&mut self, state: &[f64]) -> Vec<f64>;
}

// Example: Classical Proportional-Integral-Derivative (PID) Controller
pub struct PidController {
    kp: f64,
    ki: f64,
    kd: f64,
    setpoint: f64,
    integral: f64,
    last_error: f64,
}

impl PidController {
    pub fn new(kp: f64, ki: f64, kd: f64, setpoint: f64) -> Self {
        Self { kp, ki, kd, setpoint, integral: 0.0, last_error: 0.0 }
    }
}

impl ControlAlgorithm for PidController {
    fn step(&mut self, state: &[f64]) -> Vec<f64> {
        let current_val = state[0];
        let error = self.setpoint - current_val;
        self.integral += error * 0.01;
        let derivative = (error - self.last_error) / 0.01;
        self.last_error = error;
        
        let output = (self.kp * error) + (self.ki * self.integral) + (self.kd * derivative);
        vec![output]
    }
}

// Guardrail Filter for hard bounds
pub struct SafetyGuardrail {
    min_limit: f64,
    max_limit: f64,
}

impl SafetyGuardrail {
    pub fn filter(&self, raw_signal: Vec<f64>) -> ActuatorSignal {
        let clamped: Vec<f64> = raw_signal
            .into_iter()
            .map(|val| val.clamp(self.min_limit, self.max_limit))
            .collect();
        ActuatorSignal { commands: clamped }
    }
}

// Shiva Orchestrator Coupling Loop
pub fn run_coupling_loop<C: ControlAlgorithm>(
    mut controller: C,
    guardrail: SafetyGuardrail,
    duration: Duration,
) {
    let tick_rate = Duration::from_millis(10); // 100 Hz loop
    let start_time = Instant::now();
    let mut plant_state = vec![0.0]; // Mock state

    while start_time.elapsed() < duration {
        let loop_start = Instant::now();

        // 1. Ingest via Environment Matrix
        let env = EnvironmentMatrix { observations: plant_state.clone() };

        // 2. Evaluate Control Algorithm
        let raw_action = controller.step(&env.observations);

        // 3. Pass through Shiva Safety Guardrails
        let safe_signal = guardrail.filter(raw_action);

        // 4. Actuation update (mock plant response)
        plant_state[0] += safe_signal.commands[0] * 0.01;

        // Maintain deterministic loop timing
        if let Some(remaining) = tick_rate.checked_sub(loop_start.elapsed()) {
            std::thread::sleep(remaining);
        }
    }
}

fn main() {
    let controller = PidController::new(2.0, 0.1, 0.05, 10.0);
    let guardrail = SafetyGuardrail { min_limit: -5.0, max_limit: 5.0 };
    run_coupling_loop(controller, guardrail, Duration::from_secs(2));
}
```

#### 2. Python Binding Coupling (`bindings/python/shiva.py` / `python_example.py`)

```python
import numpy as np
import time

class ShivaControlCoupler:
    """
    Python wrapper matching Shiva's C-ABI / Python bindings.
    Couples arbitrary external algorithms (PyTorch RL, NumPy MPC) to the Shiva core.
    """
    def __init__(self, action_dim: int, lower_bounds: np.ndarray, upper_bounds: np.ndarray):
        self.action_dim = action_dim
        self.lower_bounds = lower_bounds
        self.upper_bounds = upper_bounds

    def process_guardrails(self, raw_action: np.ndarray) -> np.ndarray:
        # Enforces hard safety invariants and physical limits
        return np.clip(raw_action, self.lower_bounds, self.upper_bounds)

    def couple(self, algorithm_callback, get_plant_state, apply_actuation, frequency_hz: float = 100.0):
        dt = 1.0 / frequency_hz
        try:
            while True:
                t0 = time.perf_counter()

                # Step 1: Read state from system
                observation = get_plant_state()

                # Step 2: Compute control action using supplied algorithm
                raw_action = algorithm_callback(observation)

                # Step 3: Enforce Shiva Guardrails / Anomaly Check
                safe_action = self.process_guardrails(np.asarray(raw_action, dtype=np.float64))

                # Step 4: Dispatch to plant
                apply_actuation(safe_action)

                # Step 5: Enforce loop rate
                elapsed = time.perf_counter() - t0
                if elapsed < dt:
                    time.sleep(dt - elapsed)
        except KeyboardInterrupt:
            pass

# Example usage: Coupling a custom policy
if __name__ == "__main__":

    )

    # Replace with any control policy (e.g. TD3, SAC, LQR, or MPC)
    def policy_fn(state: np.ndarray) -> np.ndarray:
        target = 0.0
        return 0.5 * (target - state)

    mock_state = np.array([2.5])

    def get_state():
        return mock_state

    def send_actuation(action):
        global mock_state
        mock_state += action * 0.05
        print(f"State: {mock_state[0]:.3f} | Action Applied: {action[0]:.3f}")

    # Run for demonstration
```

### Multi-Input Multi-Output (MIMO) Coupler with Asynchronous Middleman (Python)

When controlling complex multi-degree-of-freedom systems (e.g., robotic arms, quadrupeds), state and action dimensions scale up. The pipeline decouples communication via an asynchronous ring buffer to keep network I/O from stalling control loops.

```python
import numpy as np
import time
import threading
from typing import Callable, Tuple

class AsyncShivaMiddleman:
    """
    Asynchronous Middleman coordinating high-frequency sensor ingestion
    with decoupled policy inference and low-level safety enforcement.
    """
    def __init__(
        self,
        state_dim: int,
        action_dim: int,
        lower_action_bounds: np.ndarray,
        upper_action_bounds: np.ndarray,
        max_rate_of_change: np.ndarray,
    ):
        self.state_dim = state_dim
        self.action_dim = action_dim
        self.lower_bounds = np.asarray(lower_action_bounds, dtype=np.float64)
        self.upper_bounds = np.asarray(upper_action_bounds, dtype=np.float64)
        self.max_slew_rate = np.asarray(max_rate_of_change, dtype=np.float64)

        # Thread-safe buffer
        self._lock = threading.Lock()
        self._latest_state = np.zeros(state_dim, dtype=np.float64)
        self._latest_safe_action = np.zeros(action_dim, dtype=np.float64)
        self._last_applied_action = np.zeros(action_dim, dtype=np.float64)
        self._running = False

    def update_telemetry(self, state: np.ndarray) -> None:
        """Called by the plant sensor ingest thread."""
        with self._lock:
            self._latest_state = np.copy(state)

    def get_latest_action(self) -> np.ndarray:
        """Called by the physical actuator output interface."""
        with self._lock:
            return np.copy(self._latest_safe_action)

    def _apply_guardrails(self, target_action: np.ndarray, dt: float) -> np.ndarray:
        """
        Enforces both positional bounding box constraints and
        slew rate (derivative) saturation limits.
        """
        # 1. Slew rate saturation: |u_k - u_{k-1}| / dt <= max_slew
        delta_u = target_action - self._last_applied_action
        max_delta = self.max_slew_rate * dt
        clamped_delta = np.clip(delta_u, -max_delta, max_delta)
        slew_limited_action = self._last_applied_action + clamped_delta

        # 2. Hard absolute bounds
        bounded_action = np.clip(slew_limited_action, self.lower_bounds, self.upper_bounds)
        self._last_applied_action = np.copy(bounded_action)
        return bounded_action

    def start_inference_worker(
        self,
        policy_fn: Callable[[np.ndarray], np.ndarray],
        frequency_hz: float = 100.0,
    ) -> threading.Thread:
        """Runs the control evaluation loop on a dedicated thread."""
        self._running = True
        dt = 1.0 / frequency_hz

        def _worker_loop():
            last_time = time.perf_counter()
            while self._running:
                now = time.perf_counter()
                elapsed = now - last_time

                if elapsed >= dt:
                    # Fetch observation
                    with self._lock:
                        obs = np.copy(self._latest_state)

                    # Compute action via policy
                    raw_action = policy_fn(obs)

                    # Pass through guardrail constraints
                    safe_action = self._apply_guardrails(np.asarray(raw_action, dtype=np.float64), elapsed)

                    # Update dispatch buffer
                    with self._lock:
                        self._latest_safe_action = safe_action

                    last_time = now
                else:
                    time.sleep(max(0.0, (dt - elapsed) / 2.0))

        thread = threading.Thread(target=_worker_loop, daemon=True)
        thread.start()
        return thread

    def stop(self) -> None:
        self._running = False

```

### Native Rust: Model Predictive Control (MPC) / State-Space Coupling

Below is an end-to-end discrete-time linear-quadratic control loop coupled directly to Shiva's environment abstraction using linear state-space matrices ($x_{k+1} = Ax_k + Bu_k$):

```rust
use std::time::{Duration, Instant};

/// Generic State-Space Matrix Representation for MIMO plants
pub struct StateSpacePlant {
    pub a_matrix: Vec<Vec<f64>>, // n x n
    pub b_matrix: Vec<Vec<f64>>, // n x m
    pub state: Vec<f64>,         // n
}

impl StateSpacePlant {
    pub fn new(a: Vec<Vec<f64>>, b: Vec<Vec<f64>>, initial_state: Vec<f64>) -> Self {
        Self { a_matrix: a, b_matrix: b, state: initial_state }
    }

    pub fn step(&mut self, control_inputs: &[f64]) -> Vec<f64> {
        let n = self.state.len();
        let m = control_inputs.len();
        let mut next_state = vec![0.0; n];

        // x_{k+1} = A * x_k + B * u_k
        for i in 0..n {
            let mut ax = 0.0;
            for j in 0..n {
                ax += self.a_matrix[i][j] * self.state[j];
            }
            let mut bu = 0.0;
            for k in 0..m {
                bu += self.b_matrix[i][k] * control_inputs[k];
            }
            next_state[i] = ax + bu;
        }

        self.state = next_state;
        self.state.clone()
    }
}

/// Dynamic Gain State-Feedback Controller (u = -K * x)
pub struct StateFeedbackController {
    pub gain_matrix_k: Vec<Vec<f64>>, // m x n
    pub setpoint: Vec<f64>,           // n
}

impl StateFeedbackController {
    pub fn compute_action(&self, current_state: &[f64]) -> Vec<f64> {
        let m = self.gain_matrix_k.len();
        let n = current_state.len();
        let mut u = vec![0.0; m];

        for i in 0..m {
            let mut feedback = 0.0;
            for j in 0..n {
                let error = current_state[j] - self.setpoint[j];
                feedback += self.gain_matrix_k[i][j] * error;
            }
            u[i] = -feedback;
        }
        u
    }
}

/// Shiva Multi-Channel Safety Guardrail with Energy Threshold Monitoring
pub struct MultiChannelGuardrail {
    pub min_limits: Vec<f64>,
    pub max_limits: Vec<f64>,
    pub max_allowable_state_norm: f64,
}

impl MultiChannelGuardrail {
    pub fn sanitize(
        &self,
        raw_action: Vec<f64>,
        current_state: &[f64],
    ) -> Result<Vec<f64>, &'static str> {
        // Anomaly / Divergence Check (Lyapunov Stability Monitoring)
        let state_energy: f64 = current_state.iter().map(|x| x * x).sum::<f64>().sqrt();
        if state_energy > self.max_allowable_state_norm {
            return Err("Emergency Stop: State space vector exceeded safety envelope.");
        }

        // Channel-wise hard saturation
        let clamped: Vec<f64> = raw_action
            .into_iter()
            .enumerate()
            .map(|(idx, val)| {
                let min = self.min_limits[idx];
                let max = self.max_limits[idx];
                val.clamp(min, max)
            })
            .collect();

        Ok(clamped)
    }
}

// Orchestrator Execution
pub fn run_state_space_orchestration() {
    // 2-State (e.g. angle, angular velocity), 1-Actuator (torque)
    let a = vec![
        vec![1.0, 0.01],
        vec![0.0, 0.99],
    ];
    let b = vec![
        vec![0.0],
        vec![0.05],
    ];
    let mut plant = StateSpacePlant::new(a, b, vec![1.5, 0.0]); // Displaced initial state

    let controller = StateFeedbackController {
        gain_matrix_k: vec![vec![12.0, 2.5]],
        setpoint: vec![0.0, 0.0],
    };

    let guardrail = MultiChannelGuardrail {
        min_limits: vec![-3.0],
        max_limits: vec![3.0],
        max_allowable_state_norm: 10.0,
    };

    let loop_dt = Duration::from_millis(10);
    for step in 0..100 {
        let t0 = Instant::now();

        // 1. Ingest State
        let current_state = plant.state.clone();

        // 2. Compute Raw Policy
        let raw_action = controller.compute_action(&current_state);

        // 3. Guardrail / Fault-Tolerance Filter
        let safe_action = match guardrail.sanitize(raw_action, &current_state) {
            Ok(act) => act,
            Err(msg) => {
                eprintln!("Step {}: {}", step, msg);
                vec![0.0] // Safe default / zero actuation
            }
        };

        // 4. Actuate Plant
        let updated_state = plant.step(&safe_action);

        if step % 20 == 0 {
            println!(
                "Step {:03} | State: [{:.3}, {:.3}] | Command: {:.3}",
                step, updated_state[0], updated_state[1], safe_action[0]
            );
        }

        if let Some(delay) = loop_dt.checked_sub(t0.elapsed()) {
            std::thread::sleep(delay);
        }
    }
}

```

### 1. Lock-Free Multi-Node Shared State (`src/nodes/core/shared_state.rs`)

Shiva's `Mothership` orchestrates asynchronous communication between the `FastDecisionNode`, `LongVisionNode`, and `GuardrailNode` using atomic cache-padded or double-buffered snapshots so low-level control loops never block on long-term inference:

```rust
use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::Arc;

pub const MAX_OBS_DIM: usize = 32;
pub const MAX_ACT_DIM: usize = 8;

/// Double-buffered, lock-free state snapshot used across Shiva nodes
pub struct ShivaSharedBuffer {
    // 0 or 1 index indicating active read buffer
    read_index: AtomicUsize,
    buffers: [ShivaStateSnapshot; 2],
}

#[derive(Clone, Copy)]
pub struct ShivaStateSnapshot {
    pub observation: [f64; MAX_OBS_DIM],
    pub obs_len: usize,
    pub safe_action: [f64; MAX_ACT_DIM],
    pub act_len: usize,
    pub timestamp_us: u64,
    pub emergency_halt: bool,
}

impl Default for ShivaStateSnapshot {
    fn default() -> Self {
        Self {
            observation: [0.0; MAX_OBS_DIM],
            obs_len: 0,
            safe_action: [0.0; MAX_ACT_DIM],
            act_len: 0,
            timestamp_us: 0,
            emergency_halt: false,
        }
    }
}

impl ShivaSharedBuffer {
    pub fn new() -> Arc<Self> {
        Arc::new(Self {
            read_index: AtomicUsize::new(0),
            buffers: [ShivaStateSnapshot::default(), ShivaStateSnapshot::default()],
        })
    }

    /// Read side (Fast Decision / Actuator Output Node)
    pub fn read_latest(&self) -> ShivaStateSnapshot {
        let idx = self.read_index.load(Ordering::Acquire);
        self.buffers[idx]
    }

    /// Write side (Middleman / Ingestion Node)
    /// Safety: Only one designated writer thread updates the non-active slot.
    pub unsafe fn write_snapshot(&mut self, new_snapshot: ShivaStateSnapshot) {
        let current_read = self.read_index.load(Ordering::Relaxed);
        let write_slot = 1 - current_read;

        self.buffers[write_slot] = new_snapshot;
        // Flip active slot atomically
        self.read_index.store(write_slot, Ordering::Release);
    }
}

```

### 2. Reinforcement Learning Brain Coupling (`src/brain/core/traits.rs` & `src/algorithms/`)

Shiva interfaces continuous actor-critic algorithms (like Soft Actor-Critic or Twin Delayed DDPG) with physical systems by abstracting the policy network as an evaluatable brain policy with deterministic and stochastic execution modes:

```rust
pub trait ShivaPolicyBrain: Send + Sync {
    /// Evaluates current observations and computes raw continuous action vectors
    fn forward(&self, observation: &[f64], deterministic: bool) -> Vec<f64>;
    
    /// Returns the input (observation) and output (action) dimensions
    fn dimensions(&self) -> (usize, usize);
}

/// Linear/MLP continuous policy network coupling (e.g., actor head of SAC or TD3)
pub struct ContinuousActorPolicy {
    pub weights_layer1: Vec<Vec<f64>>, // [hidden_dim, obs_dim]
    pub bias_layer1: Vec<f64>,
    pub weights_out: Vec<Vec<f64>>,    // [act_dim, hidden_dim]
    pub bias_out: Vec<f64>,
}

impl ContinuousActorPolicy {
    fn relu(x: f64) -> f64 {
        if x > 0.0 { x } else { 0.0 }
    }

    fn tanh(x: f64) -> f64 {
        x.tanh()
    }
}

impl ShivaPolicyBrain for ContinuousActorPolicy {
    fn dimensions(&self) -> (usize, usize) {
        let obs_dim = self.weights_layer1[0].len();
        let act_dim = self.weights_out.len();
        (obs_dim, act_dim)
    }

    fn forward(&self, observation: &[f64], _deterministic: bool) -> Vec<f64> {
        let hidden_dim = self.bias_layer1.len();
        let act_dim = self.bias_out.len();
        let mut hidden = vec![0.0; hidden_dim];

        // First dense layer + ReLU
        for h in 0..hidden_dim {
            let mut dot = self.bias_layer1[h];
            for (i, &obs) in observation.iter().enumerate() {
                dot += self.weights_layer1[h][i] * obs;
            }
            hidden[h] = Self::relu(dot);
        }

        // Output dense layer + Tanh saturation (Action bounds: [-1.0, 1.0])
        let mut action = vec![0.0; act_dim];
        for a in 0..act_dim {
            let mut dot = self.bias_out[a];
            for h in 0..hidden_dim {
                dot += self.weights_out[a][h] * hidden[h];
            }
            action[a] = Self::tanh(dot);
        }

        action
    }
}

```

### 3. Failure Engine & Fault-Tolerant Switching (`src/nodes/failure_engine/node.rs`)

When physical sensors drop or an RL algorithm produces divergence/nans, Shiva's `FailureEngine` intercepts the output and hands control over to a deterministic fallback law (e.g., standard PD or zero-torque damper):

```rust
pub enum ControllerHealth {
    Nominal,
    AnomalyDetected(&'static str),
    DegradedSensor,
    CriticalFailure,
}

pub struct ShivaFailureEngine<P, F>
where
    P: ShivaPolicyBrain,
    F: Fn(&[f64]) -> Vec<f64> + Send + Sync,
{
    primary_brain: P,
    deterministic_fallback: F,
    consecutive_anomalies: usize,
    max_tolerance: usize,
}

impl<P, F> ShivaFailureEngine<P, F>
where
    P: ShivaPolicyBrain,
    F: Fn(&[f64]) -> Vec<f64> + Send + Sync,
{
    pub fn new(primary: P, fallback: F, max_tolerance: usize) -> Self {
        Self {
            primary_brain: primary,
            deterministic_fallback: fallback,
            consecutive_anomalies: 0,
            max_tolerance,
        }
    }

    pub fn execute_fault_tolerant_step(&mut self, state: &[f64]) -> (Vec<f64>, ControllerHealth) {
        // 1. Telemetry sanity check
        let is_state_corrupt = state.iter().any(|&x| x.is_nan() || x.is_infinite());
        if is_state_corrupt {
            let fallback_action = (self.deterministic_fallback)(state);
            return (fallback_action, ControllerHealth::DegradedSensor);
        }

        // 2. Primary Brain inference
        let candidate_action = self.primary_brain.forward(state, true);

        // 3. Action anomaly check (e.g., NaN outputs from network weights)
        let is_action_corrupt = candidate_action.iter().any(|&u| u.is_nan() || u.is_infinite());

        if is_action_corrupt {
            self.consecutive_anomalies += 1;
            let fallback_action = (self.deterministic_fallback)(state);

            if self.consecutive_anomalies >= self.max_tolerance {
                (fallback_action, ControllerHealth::CriticalFailure)
            } else {
                (fallback_action, ControllerHealth::AnomalyDetected("Corrupted action vector from neural core"))
            }
        } else {
            self.consecutive_anomalies = 0;
            (candidate_action, ControllerHealth::Nominal)
        }
    }
}
```

```rust
        }
```

### Deployment Architecture Overview

A production Shiva deployment operates across three main layers:

* **Container / Process Layer:** A lightweight container running the compiled native binary (`shiva-runtime`) configured for POSIX real-time scheduling (`SCHED_FIFO`) to minimize thread preemption jitter.

* **Orchestrator Lifecycle Management:** Declarative configuration defining algorithm hyperparameters, safety bounds, fallback rules, and node topologies.

```rust
            last_action = safe_action.clone();

            // 4. Dispatch to physical actuators
            self.write_actuators(&safe_action);

            tick += 1;
            if tick % 100 == 0 {
                println!("[SHIVA-HEARTBEAT] Tick: {} | Action: {:?}", tick, safe_action);
            }

            // Real-time sleep compensation
            if let Some(remaining) = period.checked_sub(start_instant.elapsed()) {
                std::thread::sleep(remaining);
            }
        }

        println!("[SHIVA] Shutdown sequence executed. Plant set to safe state.");

        // Policy / Controller output
        vec![1.5, -2.0]

            .zip(previous.iter())

                slew_limited.clamp(
                    self.config.guardrail.lower_bounds[idx],
                    self.config.guardrail.upper_bounds[idx],
                )
            })
            .collect()
    }

        // Flushes safe commands to the actuator drivers
    }
}
```

### 3. IPC Hardware Ingestion Daemon (Python Sidecar)

In deployments where high-level drivers or neural network models run in Python while the safety engine runs natively, an IPC sidecar routes telemetry over a local Unix domain socket:

```python
import socket
import struct
import time
import numpy as np

SOCKET_PATH = "/tmp/shiva_ipc.sock"

class ShivaDeploymentBridge:
    def __init__(self, obs_dim: int, act_dim: int):
        self.obs_dim = obs_dim
        self.act_dim = act_dim
        self.client = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)

    def connect(self, timeout_secs: float = 5.0):
        start_time = time.time()
        while time.time() - start_time < timeout_secs:
            try:
                self.client.connect(SOCKET_PATH)
                print(f"[BRIDGE] Connected to Shiva native socket at {SOCKET_PATH}")
                return
            except (FileNotFoundError, ConnectionRefusedError):
                time.sleep(0.2)
        raise TimeoutError("Could not connect to Shiva runtime socket.")

    def step(self, observation: np.ndarray) -> np.ndarray:
        """
        Sends observation payload and receives validated, safe action commands.
        Format: [obs_len (I) | obs (d...)] -> [act_len (I) | acts (d...)]
        """
        # Pack observation
        obs_payload = struct.pack(f"=I{self.obs_dim}d", self.obs_dim, *observation)
        self.client.sendall(obs_payload)

        # Receive sanitized action
        header = self.client.recv(4)
        if not header:
            raise ConnectionResetError("Shiva backend closed communication.")
        
        (act_len,) = struct.unpack("=I", header)
        action_data = self.client.recv(8 * act_len)
        safe_actions = struct.unpack(f"={act_len}d", action_data)

        return np.array(safe_actions, dtype=np.float64)

    def close(self):
        self.client.close()

if __name__ == "__main__":
    bridge = ShivaDeploymentBridge(obs_dim=2, act_dim=2)
    try:
        bridge.connect()
        while True:
            # Example telemetry payload
            mock_obs = np.array([0.1, -0.4], dtype=np.float64)
            safe_command = bridge.step(mock_obs)
            print(f"[ACTUATOR DISPATCH] Output: {safe_command}")
            time.sleep(0.01)
    except KeyboardInterrupt:
        bridge.close()
```

### Verification and Health Check Checklist

When validating a freshly deployed Shiva instance:

1. **Jitter Verification:** Run `chrt -f 80 /usr/local/bin/shiva-runtime` and measure delta timestamps across consecutive ticks to confirm standard deviation stays below hardware deadlines (typically $<100\,\mu\text{s}$).
2. **Boundary Stress Testing:** Feed saturated vectors (`[-1e6, 1e6]`) to verify the guardrail nodes clamp output arrays to the configured min/max parameters.
3. **Failover Response:** Intentionally send `NaN` observations to confirm the `FailureEngine` invokes the deterministic fallback mode within a single control period.

namespace shiva::dynamics {

// Spatial 6D vector representing twist (angular; linear) or wrench (torque; force)
struct alignas(32) SpatialVector {
    double data[6]; // [0..2]: angular (wx, wy, wz), [3..5]: linear (vx, vy, vz)

    inline double& operator[](std::size_t i) { return data[i]; }
    inline const double& operator[](std::size_t i) const { return data[i]; }

    inline SpatialVector operator+(const SpatialVector& o) const {
        SpatialVector r;
        for (int i = 0; i < 6; ++i) r.data[i] = data[i] + o.data[i];
        return r;
    }

    inline SpatialVector operator-(const SpatialVector& o) const {
        SpatialVector r;
        for (int i = 0; i < 6; ++i) r.data[i] = data[i] - o.data[i];
        return r;
    }
};

// 6x6 Spatial Inertia Matrix for a rigid body
struct alignas(64) SpatialInertia {
    // I_spatial = [  I_rot     m * [c]_x ]
    //             [ -m * [c]_x   m * I_3  ]
    double m;             // mass
    double c[3];          // center of mass offset
    double I_rot[3][3];   // rotational inertia tensor at origin

    inline SpatialVector apply(const SpatialVector& a) const {
        SpatialVector f;
        // Angular momentum rate
        double mc_cross_v[3] = {
            m * (c[1] * a.data[5] - c[2] * a.data[4]),
            m * (c[2] * a.data[3] - c[0] * a.data[5]),
            m * (c[0] * a.data[4] - c[1] * a.data[3])
        };
        for (int i = 0; i < 3; ++i) {
            f.data[i] = I_rot[i][0] * a.data[0] + I_rot[i][1] * a.data[1] + I_rot[i][2] * a.data[2] + mc_cross_v[i];
        }

        // Linear force rate
        double omega_cross_c[3] = {
            a.data[1] * c[2] - a.data[2] * c[1],
            a.data[2] * c[0] - a.data[0] * c[2],
            a.data[0] * c[1] - a.data[1] * c[0]
        };
        for (int i = 0; i < 3; ++i) {
            f.data[3 + i] = m * a.data[3 + i] - m * omega_cross_c[i];
        }
        return f;
    }
};

// Spatial Cross Product Operator: [v] x_spatial
inline SpatialVector spatial_cross(const SpatialVector& v, const SpatialVector& u) {
    SpatialVector res;
    // angular part = v_w x u_w
    res.data[0] = v.data[1] * u.data[2] - v.data[2] * u.data[1];
    res.data[1] = v.data[2] * u.data[0] - v.data[0] * u.data[2];
    res.data[2] = v.data[0] * u.data[1] - v.data[1] * u.data[0];

    // linear part = v_w x u_v + v_v x u_w
    res.data[3] = (v.data[1] * u.data[5] - v.data[2] * u.data[4]) + (v.data[4] * u.data[2] - v.data[5] * u.data[1]);
    res.data[4] = (v.data[2] * u.data[3] - v.data[0] * u.data[5]) + (v.data[5] * u.data[0] - v.data[3] * u.data[2]);
    res.data[5] = (v.data[0] * u.data[4] - v.data[1] * u.data[3]) + (v.data[3] * u.data[1] - v.data[4] * u.data[0]);
    return res;
}

// Spatial Force Cross Product: [v] x_spatial^* f
inline SpatialVector spatial_cross_dual(const SpatialVector& v, const SpatialVector& f) {
    SpatialVector res;
    // res_w = v_w x f_w + v_v x f_v
    res.data[0] = (v.data[1] * f.data[2] - v.data[2] * f.data[1]) + (v.data[4] * f.data[5] - v.data[5] * f.data[4]);

template <std::size_t NUM_JOINTS>
class DeterministicRNEA {
public:
    struct LinkParameters {
        SpatialInertia inertia;
        SpatialVector S; // Joint motion subspace vector (e.g. [0, 0, 1, 0, 0, 0] for revolute Z)
        double X_parent[6][6]; // Spatial transform from parent to this link
    };

    explicit DeterministicRNEA(const std::array<LinkParameters, NUM_JOINTS>& params)
        : params_(params) {}

    void compute_inverse_dynamics(
        const std::array<double, NUM_JOINTS>& q,
        const std::array<double, NUM_JOINTS>& qd,
        const std::array<double, NUM_JOINTS>& qdd,
        const SpatialVector& base_accel, // Gravity vector set at base (e.g., [0,0,0, 0,0, 9.81])
        std::array<double, NUM_JOINTS>& tau_out
    ) noexcept {
        // Forward Kinematics Sweep: Base to Tip
        for (std::size_t i = 0; i < NUM_JOINTS; ++i) {
            SpatialVector v_joint;
            for (int k = 0; k < 6; ++k) v_joint.data[k] = params_[i].S.data[k] * qd[i];

            if (i == 0) {
                v_[i] = v_joint;
                // a_i = X_parent * a_base + S_i * qdd_i + v_i x v_joint
                SpatialVector transformed_a;
                transform_spatial(params_[i].X_parent, base_accel, transformed_a);
                a_[i] = transformed_a;
                for (int k = 0; k < 6; ++k) a_[i].data[k] += params_[i].S.data[k] * qdd[i];
            } else {
                SpatialVector transformed_v;
                transform_spatial(params_[i].X_parent, v_[i - 1], transformed_v);
                v_[i] = transformed_v + v_joint;

                SpatialVector transformed_a;
                transform_spatial(params_[i].X_parent, a_[i - 1], transformed_a);
                SpatialVector coriolis = spatial_cross(v_[i], v_joint);
                a_[i] = transformed_a + coriolis;
                for (int k = 0; k < 6; ++k) a_[i].data[k] += params_[i].S.data[k] * qdd[i];
            }

            // Inertial force: f_i = I_i * a_i + v_i x^* (I_i * v_i)
            SpatialVector Iv = params_[i].inertia.apply(v_[i]);
            SpatialVector Ia = params_[i].inertia.apply(a_[i]);
            f_[i] = Ia + spatial_cross_dual(v_[i], Iv);
        }

        // Backward Recursion Sweep: Tip to Base
        for (int i = static_cast<int>(NUM_JOINTS) - 1; i >= 0; --i) {
            // Joint torque projection: tau_i = S_i^T * f_i
            double torque = 0.0;
            for (int k = 0; k < 6; ++k) {
                torque += params_[i].S.data[k] * f_[i].data[k];
            }
            tau_out[i] = torque;

            // Transmit load to parent
            if (i > 0) {
                SpatialVector f_parent;
                transform_spatial_transpose(params_[i].X_parent, f_[i], f_parent);
                f_[i - 1] = f_[i - 1] + f_parent;
            }
        }
    }

private:
    static inline void transform_spatial(const double X[6][6], const SpatialVector& src, SpatialVector& dst) noexcept {
        for (int r = 0; r < 6; ++r) {
            dst.data[r] = 0.0;
            for (int c = 0; c < 6; ++c) {
                dst.data[r] += X[r][c] * src.data[c];
            }
        }
    }

    static inline void transform_spatial_transpose(const double X[6][6], const SpatialVector& src, SpatialVector& dst) noexcept {
        for (int r = 0; r < 6; ++r) {
            dst.data[r] = 0.0;
            for (int c = 0; c < 6; ++c) {
                dst.data[r] += X[c][r] * src.data[c]; // Transposed indexing
            }
        }
    }

    std::array<LinkParameters, NUM_JOINTS> params_;
    std::array<SpatialVector, NUM_JOINTS> v_;
    std::array<SpatialVector, NUM_JOINTS> a_;
    std::array<SpatialVector, NUM_JOINTS> f_;
};

use std::simd::num::SimdFloat;

#[repr(C, align(64))]
pub struct DynamicObstacle {
    pub x: f64,
    pub y: f64,
    pub vx: f64,
    pub vy: f64,
    pub radius: f64,
    pub _pad: [f64; 3], // Enforce 64-byte boundary

#[repr(C, align(64))]
pub struct CompositeCbfResult {
    pub h_val: f64,
    pub lf_h: f64,
    pub lg_h: [f64; 2],
    pub partial_t: f64,
}

pub struct VectorizedCbfEvaluator {
    pub kappa: f64,
}

impl VectorizedCbfEvaluator {
    #[inline(always)]
    pub fn evaluate_obstacles(
        &self,
        robot_pos: [f64; 2],
        robot_vel: [f64; 2],
        obstacles: &[DynamicObstacle],
        result: &mut CompositeCbfResult,
    ) {
        let n = obstacles.len();
        if n == 0 {
            result.h_val = 1e6;
            result.lf_h = 0.0;
            result.lg_h = [0.0, 0.0];
            result.partial_t = 0.0;
            return;
        }

        // Stack-allocated buffers (max 32 dynamic obstacles without allocation)
        const MAX_OBSTACLES: usize = 32;
        assert!(n <= MAX_OBSTACLES);
        
        let mut h_vals = [0.0f64; MAX_OBSTACLES];
        let mut grad_x = [0.0f64; MAX_OBSTACLES];
        let mut grad_y = [0.0f64; MAX_OBSTACLES];
        let mut partial_ts = [0.0f64; MAX_OBSTACLES];

        let rx = robot_pos[0];
        let ry = robot_pos[1];
        let rvx = robot_vel[0];
        let rvy = robot_vel[1];

        // Process obstacles in 4-wide SIMD chunks
        let mut min_h = f64::INFINITY;

        for (i, obs) in obstacles.iter().enumerate() {
            let dx = rx - obs.x;
            let dy = ry - obs.y;
            let dist_sq = dx * dx + dy * dy;
            let r_sq = obs.radius * obs.radius;

            // Distance barrier: h_i = ||p - p_obs||^2 - r^2
            let h_i = dist_sq - r_sq;
            h_vals[i] = h_i;
            if h_i < min_h { min_h = h_i; }

            // Spatial gradients
            grad_x[i] = 2.0 * dx;
            grad_y[i] = 2.0 * dy;

            // Explicit time derivative: dh/dt = -2*(dx*vx_obs + dy*vy_obs)
            partial_ts[i] = -2.0 * (dx * obs.vx + dy * obs.vy);
        }

        // Compute Softmin via Log-Sum-Exp with numerical stabilization using min_h
        let mut sum_exp = 0.0f64;
        let mut exp_weights = [0.0f64; MAX_OBSTACLES];

        for i in 0..n {
            let shifted = -self.kappa * (h_vals[i] - min_h);
            let val = shifted.exp();
            exp_weights[i] = val;
            sum_exp += val;
        }

        let inv_sum = 1.0 / sum_exp;
        let h_soft = min_h - (1.0 / self.kappa) * sum_exp.ln();

        let mut composite_grad_x = 0.0f64;
        let mut composite_grad_y = 0.0f64;
        let mut composite_partial_t = 0.0f64;

        for i in 0..n {
            let w_i = exp_weights[i] * inv_sum;
            composite_grad_x += w_i * grad_x[i];
            composite_grad_y += w_i * grad_y[i];
            composite_partial_t += w_i * partial_ts[i];
        }

        // Under double integrator model: q = [x, y], dq = [vx, vy], u = [ax, ay]
        // L_f h = grad_p * v
        // L_g h = grad_p (when input directly controls acceleration)
        result.h_val = h_soft;
        result.lf_h = composite_grad_x * rvx + composite_grad_y * rvy;
        result.lg_h[0] = composite_grad_x;
        result.lg_h[1] = composite_grad_y;
        result.partial_t = composite_partial_t;
    }
}

A heavy robotic arm moving at high speed toward a joint limit cannot stop instantaneously; clamping velocity when the boundary is breached will still lead to mechanical impact due to actuator saturation.Boundary Chattering & Limit Cycles: Abrupt rule switches introduce discontinuous vector fields, causing high-frequency oscillations (chatter) around safety thresholds. This induces mechanical fatigue, motor overheating, and sensor noise spikes.Deadlocks: Emergency stops freeze the system without providing a dynamically feasible recovery trajectory, requiring manual human resets in industrial environments.Control Barrier Functions (CBFs) solve these issues by evaluating safety forward in time. Instead of asking "am I safe right now?", a CBF evaluates "is there an admissible control input right now that guarantees I can remain safe in the future, given my current momentum and actuator capacity?"By transforming safety constraints into continuous, affine inequalities over the control inputs, the Guardrail Node acts as a smooth filter. When the robot operates well inside safe margins, the Guardrail passes the Fast Decision Node's intents with zero modification. As the system approaches a safety boundary, the Guardrail smoothly deflects the trajectory along the tangent of the barrier, preserving operational momentum while guaranteeing constraint satisfaction.24.2 THE SIM-TO-REAL GAP: CAUSES, MITIGATIONS, AND TESTINGDeploying machine learning models and dynamic controllers trained in virtual environments onto real-world hardware is notoriously difficult. In simulation, gravity is exact, time can be paused, friction is uniform, and sensor data arrives on schedule. In the physical world, physics engines are imperfect, sensors are noisy, and mechanical structures flex.Primary Causes of Sim-to-Real Discrepancy:Actuator Dynamics & Latency: Most physics engines simulate ideal motors that achieve commanded torques instantaneously. Standard general-purpose operating systems optimize for average-case throughput rather than worst-case execution time, making them unsuitable for real-time robotic control out of the box.25.1 LINUX PREEMPT_RT ESSENTIALSThe standard Linux kernel prioritizes background batch processing, file system caching, and fair resource sharing. A thread can be arbitrarily preempted or delayed by kernel locks, interrupts, or page cache flushes. The PREEMPT_RT patch transforms Linux into a hard real-time operating system by altering fundamental kernel mechanics:Making Spinlocks Preemptible: In standard Linux, code executing inside a spinlock disables kernel preemption. Under PREEMPT_RT, spinlocks are converted into sleeping mutexes (rt_mutex), allowing high-priority real-time threads to preempt code running inside critical sections.Threaded Interrupt Handlers: Hardware interrupts (IRQs) are forced to run in dedicated kernel threads. This allows real-time user-space control tasks to be scheduled at a higher priority than hardware interrupt handlers, preventing network cards or USB ports from starving control loops.Priority Inheritance Mutexes: To prevent priority inversion—where a low-priority thread holding a shared lock blocks a high-priority thread while being preempted by an intermediate-priority task—rt_mutex automatically elevates the low-priority thread's priority to match the blocked thread until the lock is released.25.2 PROCESSOR AFFINITY, CORE ISOLATION, AND CACHE WARMINGTo achieve microsecond-level determinism on modern multi-core processors (such as AMD EPYC, Intel Xeon, or ARM Cortex-A78AE), control threads must be physically isolated from the rest of the OS:Kernel Core Isolation (isolcpus / nohz_full): By passing configuration parameters to the Linux bootloader, specific CPU cores (e.g., Cores 2 and 3) are completely removed from the general OS scheduler. The kernel will never assign arbitrary background tasks, user shell commands, or software timers to these cores.Interrupt Shielding (irqbalance exclusions): Ensure that hardware device interrupts (Ethernet, PCIe, NVMe) are routed exclusively to non-isolated housekeeping cores (such as Core 0 and Core 1).Thread Pinning: Real-time worker threads (GuardrailNode and MiddleMan) are explicitly pinned to isolated cores using processor affinity directives (pthread_setaffinity_np). Once pinned, they run uninterrupted from initialization to shutdown.Memory Locking (mlockall): A major source of latency spikes is page faulting—when a thread accesses a memory address that has been swapped to disk or has not yet been physically mapped by the memory management unit (MMU). Real-time processes must lock their entire virtual address space into physical RAM on startup, pre-faulting the stack and heap to ensure that memory accesses never trigger MMU page faults during runtime.Cache Line Warming: Before entering nominal control execution, real-time algorithms should cycle through their working data structures several times to ensure all critical instructions and lookup tables reside in L1/L2 instruction and data caches.MODULE 26: COMMON FAILURE PATTERNS & ROOT CAUSE ANALYSISUnderstanding how robotic software fails in practice is essential for building resilient systems.
